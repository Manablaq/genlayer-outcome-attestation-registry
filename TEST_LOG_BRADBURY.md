
Likely cause:

The generic LLM/web resolver is too fragile for Bradbury consensus. The prompt asks the model for `evidence_facts`, while the contract validates/stores `evidence_digest`, and the validator re-runs web+LLM work while also requiring an exact evidence digest. A safer v2 should use a deterministic web JSON resolver for structured API evidence and reserve LLM judgment for semantic-only profiles.

## Patch: v2 Resolver Hardening

- Coerce malformed/non-dict LLM output into structured `error` results.
- Use non-comparative validator logic that validates normalized schema and bounds.
- Keep deterministic evidence digest generated by contract code.
